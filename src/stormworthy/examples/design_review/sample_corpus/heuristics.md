# Usability heuristics reference

Original one-line summaries for this example corpus. Canonical sources: Nielsen Norman Group's
ten usability heuristics (https://www.nngroup.com/articles/ten-usability-heuristics/) and Don
Norman's *The Design of Everyday Things*.

## Nielsen's ten

1. **Visibility of system status** — the UI says what is happening, promptly.
2. **Match between system and the real world** — the users' words, not the org chart's.
3. **User control and freedom** — clearly marked exits; undo over confirmation walls.
4. **Consistency and standards** — one meaning per word, per icon, per color.
5. **Error prevention** — remove error-prone conditions instead of writing better error copy.
6. **Recognition rather than recall** — options visible, not memorized.
7. **Flexibility and efficiency** — accelerators for experts that stay invisible to novices.
8. **Aesthetic and minimalist design** — every extra element competes with the relevant ones.
9. **Help users recognize, diagnose, recover from errors** — plain language, constructive next step.
10. **Help and documentation** — searchable, task-focused, concrete.

## Norman

**Affordance** (what an element can do), **signifier** (what tells you it can), **feedback**
(what confirms it did). A control that signals one action and performs another is a dishonest
affordance — high severity.

## Laws

- **Hick's law**: decision time grows with the number and complexity of choices — overlapping
  menu labels are a findability tax.
- **Fitts's law**: acquisition time grows with distance and shrinks with target size.
- **Miller's limit**: working memory holds about seven items; don't make the nav a memory test.

Rule of use: name the heuristic and tie the finding to it; "looks off" is not a finding.
